# Vibepollo 1.15.31 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release Vibepollo 1.15.31 with a clean embedded-Web-UI toolchain, no regression in protected native behavior, and an exactly aligned Windows installation.

**Architecture:** Repair the Web UI in attributable layers: line-ending/tooling contract, runnable unit harness, application/config typing, and WebRTC typing. Preserve native runtime semantics, then build and qualify the final Windows artifact through deterministic, independent, and hardware gates before publishing.

**Tech Stack:** Vue 3, TypeScript 5.9, ESLint 8, Prettier 3, Vitest, Vite 6, CMake, MinGW/MSYS2, Catch2/CTest, Inno Setup 6, GitHub CLI, Windows LocalSystem service.

**Spec:** `docs/superpowers/plans/2026-08-17-v1.15.31-design.md`

## Global Constraints

- Release version is exactly `1.15.31`.
- Do not relax TypeScript strictness or ESLint rules; do not add `any`, `@ts-ignore`, `@ts-nocheck`, or unlimited disable comments.
- Do not change Vibelight, display restore semantics, secure-input ownership, mic/audio behavior, runtime GPU priority, game settings, bitrate, or private launchers.
- The protected native comparison is 400 total / 358 pass / 9 skip / 33 known failures; compare failure identities, not only counts.
- Build the shipping artifact from the final release commit with `BRANCH=master` and `BUILD_VERSION=1.15.31` and verify the embedded commit after installation.
- Preserve installed `sunshine.conf` and `apps.json` byte-for-byte.
- Never force-kill the service or an active stream. Use the tray/web lifecycle and the installer/service controls.
- Run the public-repo privacy scan before every push and release.
